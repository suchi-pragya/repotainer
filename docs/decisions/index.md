# Decisions

Architectural decision records (ADRs) preserve significant choices and why they were made. Routine implementation details do not need a record.

| ADR | Status | Subject |
| --- | --- | --- |
| [0001](0001-file-based-project-context.md) | Accepted | File-based project context |

Use `NNNN-short-decision.md` with the next unused number and the [template](template.md). A few paragraphs are usually enough.

- Use `proposed`, `accepted`, `rejected`, or `superseded`. User agreement is required before marking a decision accepted.
- Capture the problem, meaningful alternatives, choice, reasoning, and consequences. Link relevant source paths or verification evidence.
- Acceptance does not mean implementation is complete; state implementation and verification separately.
- Preserve accepted reasoning. When a choice changes materially, create a new ADR and link it from the old one as its replacement.
